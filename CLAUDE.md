# MangaG — платформа для художников комиксов и манги

> Курсовой проект
> **Автор:** Солодкий Максим, группа **3ПО-9**
> **Тема:** «Платформа для художников комиксов и манги (постраничный просмотр, донаты автору, система глав)»
> **Ориентир по функционалу и UX:** [mangalib.me](https://mangalib.me/)

Этот файл — главный документ проекта: описание, стек, структура, правила кода и
пошаговый план разработки. Перед началом любой задачи сверяйся с ним и отмечай
выполненные пункты в разделе «План разработки» (`[ ]` → `[x]`).

## 1. Идея проекта

Веб-приложение, где:

- **Читатели** находят комиксы/мангу в каталоге, читают главы постранично
  (как на mangalib), добавляют тайтлы в закладки, оставляют комментарии,
  ставят оценки и поддерживают авторов донатами.
- **Авторы (художники)** создают свои тайтлы, загружают главы (набор
  изображений-страниц), управляют порядком страниц, публикуют главы и
  видят статистику просмотров и полученных донатов.
- **Администратор** модерирует контент и пользователей.

Главные фичи по теме работы:

1. **Система глав** — тайтл → тома → главы → страницы; черновик/публикация,
   сортировка, навигация «предыдущая / следующая глава».
2. **Постраничный просмотр (читалка)** — режимы «по одной странице» и
   «лента (вертикальный скролл)», управление стрелками/кликом/свайпом,
   предзагрузка следующих страниц, запоминание прогресса чтения.
3. **Донаты автору** — кнопка «Поддержать автора» на странице тайтла и в
   конце главы, выбор суммы, сообщение автору, история донатов, баланс
   автора. Оплата — **учебная имитация** (тестовый платёжный шлюз без
   реальных денег), с возможностью позже подключить ЮKassa в тестовом режиме.

## 2. Технологический стек

Стек выбран «современный, но посильный для студента»: всё на JavaScript/TypeScript,
один язык на фронте и бэке, минимум инфраструктуры.

| Слой            | Технология                                                  | Зачем                                       |
| --------------- | ----------------------------------------------------------- | ------------------------------------------- |
| Frontend        | **React 18 + Vite + TypeScript**                            | SPA, быстрая сборка                         |
| Роутинг         | **React Router v6**                                         | страницы каталога, тайтла, читалки, профиля |
| Стили           | **Tailwind CSS**                                            | быстрая адаптивная вёрстка, тёмная тема     |
| Запросы         | **axios + TanStack Query**                                  | кэш, загрузка, ошибки                       |
| Состояние       | **Zustand**                                                 | авторизация, настройки читалки              |
| Backend         | **Node.js 20+ + Express 5**                                 | REST API                                    |
| ORM / БД        | **Prisma 6 + SQLite** (dev) / PostgreSQL (опц. prod)        | простая БД-файл, миграции                   |
| Авторизация     | **JWT** (access token) + **bcrypt**                         | регистрация/вход, роли                      |
| Загрузка файлов | **multer** + **sharp**                                      | приём страниц, сжатие, превью обложек       |
| Валидация       | **zod 4**                                                   | проверка входных данных на бэке             |

## 4. Модель данных (Prisma, черновик)

```
User        id, email, username, passwordHash, avatarUrl, bio,
            role (READER | AUTHOR | ADMIN), balance, createdAt
Title       id, slug, name, altName, description, coverUrl,
            type (MANGA | MANHWA | MANHUA | COMIC), status (ONGOING | COMPLETED | FROZEN),
            ageRating, year, authorId → User, views, createdAt, updatedAt
Genre       id, name, slug                         (многие-ко-многим с Title)
Chapter     id, titleId → Title, volume, number (Float: 10.5), name,
            isPublished, publishedAt, views, createdAt
Page        id, chapterId → Chapter, order, imageUrl, width, height
Bookmark    id, userId, titleId, list (READING | PLANNED | COMPLETED | DROPPED | FAVORITE)
ReadProgress id, userId, titleId, chapterId, pageOrder, updatedAt
Rating      id, userId, titleId, score (1–10)       (уникальная пара user+title)
Comment     id, userId, titleId?, chapterId?, text, parentId? (ответы), createdAt
Like        id, userId, chapterId                   (лайк главы)
Donation    id, fromUserId?, toAuthorId, titleId?, amount, message,
            status (PENDING | PAID | FAILED), paymentId, createdAt
Payout      id, authorId, amount, status, createdAt (опц.: вывод средств автором)
```

Связи: `User 1—N Title`, `Title 1—N Chapter`, `Chapter 1—N Page`,
`Title N—M Genre`, `User 1—N Donation (отправленные / полученные)`.

ER-диаграмму положить в `docs/er-diagram.png`.

## 5. REST API (основные эндпоинты)

Префикс: `/api`. Ответы — JSON. Ошибки — `{ "error": "сообщение" }`.

**Auth**

- `POST /auth/register` · `POST /auth/login` · `GET /auth/me`

**Пользователи**

- `GET /users/:username` — публичный профиль (тайтлы автора, статистика)
- `PATCH /users/me` — редактирование профиля, аватар
- `POST /users/me/become-author` — стать автором

**Тайтлы**

- `GET /titles?search=&genre=&type=&status=&sort=popular|new|rating&page=` — каталог
- `GET /titles/:slug` — карточка тайтла (+жанры, рейтинг, автор)
- `POST /titles` · `PATCH /titles/:id` · `DELETE /titles/:id` — автор/админ
- `POST /titles/:id/cover` — загрузка обложки

**Главы и страницы**

- `GET /titles/:id/chapters` — список глав (опубликованных; автору — все)
- `GET /chapters/:id` — глава + страницы + id соседних глав
- `POST /titles/:id/chapters` · `PATCH /chapters/:id` · `DELETE /chapters/:id`
- `POST /chapters/:id/pages` — загрузка нескольких изображений (multipart)
- `PATCH /chapters/:id/pages/order` — изменить порядок страниц
- `DELETE /pages/:id`
- `POST /chapters/:id/publish`

**Чтение и активность**

- `POST /chapters/:id/view` — счётчик просмотров
- `PUT /progress` — сохранить прогресс (titleId, chapterId, page)
- `GET /bookmarks` · `PUT /bookmarks/:titleId` · `DELETE /bookmarks/:titleId`
- `PUT /titles/:id/rating`
- `GET/POST /comments?titleId=|chapterId=` · `DELETE /comments/:id`
- `POST /chapters/:id/like`

**Донаты**

- `POST /donations` — создать донат → возвращает ссылку на «оплату»
- `POST /donations/:id/confirm` — подтверждение учебным шлюзом (webhook-имитация)
- `GET /donations/sent` · `GET /donations/received` — история
- `GET /authors/:id/donations/top` — топ поддержавших

**Админ**

- `GET /admin/users` · `PATCH /admin/users/:id/role` · `DELETE /admin/titles/:id`
- `DELETE /admin/comments/:id`

## 6. Страницы клиента

| Маршрут                      | Страница         | Содержимое                                                                                                                    |
| ---------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `/`                          | Главная          | баннер, «Популярное», «Новые главы», «Новинки»                                                                                |
| `/catalog`                   | Каталог          | фильтры (жанр, тип, статус), сортировка, поиск, пагинация                                                                     |
| `/title/:slug`               | Тайтл            | обложка, описание, жанры, рейтинг, кнопки «Читать / Продолжить», закладки, список глав, комментарии, блок «Поддержать автора» |
| `/title/:slug/ch/:chapterId` | Читалка          | постраничный/ленточный режим, навигация, настройки, комментарии к главе, донат в конце главы                                  |
| `/login`, `/register`        | Вход/регистрация | формы с валидацией                                                                                                            |
| `/user/:username`            | Профиль          | аватар, закладки по спискам, тайтлы автора                                                                                    |
| `/studio`                    | Кабинет автора   | мои тайтлы, создание/редактирование, главы, загрузка страниц drag&drop, статистика, донаты                                    |
| `/donations`                 | Мои донаты       | отправленные/полученные, баланс                                                                                               |
| `/pay/:donationId`           | Учебная оплата   | имитация платёжной формы (успех/отказ)                                                                                        |
| `/admin`                     | Админка          | пользователи, модерация                                                                                                       |
| `*`                          | 404              |                                                                                                                               |

### Читалка — требования

- Режимы: **постраничный** (одна страница на экран) и **лента** (вертикально).
- Управление: клик по левой/правой половине, `←/→`, `A/D`, свайп на телефоне.
- Верхняя панель: название тайтла, выбор главы (выпадающий список), номер
  страницы `5 / 32`, кнопка настроек; скрывается при чтении.
- Нижний прогресс-бар страниц, переход на произвольную страницу.
- Предзагрузка 2–3 следующих изображений; `loading="lazy"` в режиме ленты.
- На последней странице — экран «Глава окончена»: следующая глава,
  лайк, **«Поддержать автора»**.
- Настройки (сохраняются в localStorage): режим, ширина изображения,
  фон (тёмный/светлый), направление чтения (слева-направо / справа-налево для манги).
- Автосохранение прогресса чтения (для авторизованных — на сервер).

## 9. Чек-лист приёмки (сценарии)

1. Гость открывает каталог, фильтрует по жанру, открывает тайтл, читает главу.
2. Пользователь регистрируется, добавляет тайтл в «Читаю», ставит оценку.
3. Читает главу в постраничном режиме, закрывает вкладку, возвращается —
   кнопка «Продолжить» ведёт на ту же главу и страницу.
4. Переключает режим на «ленту», меняет направление чтения — настройки сохранились.
5. В конце главы жмёт «Поддержать автора», донатит 100 ₽, проходит учебную оплату;
   донат появляется в истории, баланс автора увеличился.
6. Пользователь становится автором, создаёт тайтл, загружает обложку,
   создаёт главу, загружает 10 страниц, меняет порядок, публикует — глава
   видна в каталоге и читается.
7. Админ меняет роль пользователя и удаляет комментарий.

## 10. Команды

```bash
npm install                     # установка зависимостей всех workspaces
npm run db:migrate -w server    # миграции Prisma
npm run db:seed -w server       # демо-данные
npm run dev                     # client (5173) + server (4000) одновременно
npm run test                    # тесты
npm run lint                    # линтер
npm run build                   # сборка клиента
```

Первый запуск сервера:

```bash
cp server/.env.example server/.env   # затем поменять JWT_SECRET
npm install
npm run db:migrate -w server         # создаст server/prisma/dev.db
npm run db:seed -w server
npm run dev                          # API на http://localhost:4000/api
```

Проверка: `GET http://localhost:4000/api/health` → `{ "status": "ok" }`.
Тесты сервера используют отдельную базу `server/prisma/test.db`
(создаётся автоматически в `tests/globalSetup.js`).

Демо-аккаунты (после seed): `reader@mangag.local`, `author@mangag.local`,
`admin@mangag.local`, пароль `password123`.

## 11. Правила для разработки (в т.ч. для ИИ-ассистента)

- Язык интерфейса — **русский**; код, имена переменных и коммиты — на английском
  (комментарии в коде можно на русском).
- Код должен выглядеть как аккуратная студенческая работа: понятные имена,
  без переусложнения, без лишних абстракций и «enterprise»-паттернов.
- Бэкенд: маршрут → контроллер → (сервис) → Prisma. Вся проверка входных данных — zod.
- Любое изменение данных проверяет права (владелец или админ).
- Секреты только в `.env`, в репозиторий попадает `.env.example`.
- Загруженные файлы не коммитить (кроме демо-изображений для seed).
- Деньги хранить в **копейках (Int)**, отображать в рублях.
- После каждого этапа: проект запускается, сценарии этапа работают, коммит
  с понятным сообщением (`feat: reader page mode`, `fix: ...`).
- Отмечать выполненные пункты плана в этом файле.
- Сервер — ES-модули (`"type": "module"`), импорты с расширением `.js`.
- Express 5 сам ловит ошибки из `async`-обработчиков: в контроллерах не нужен
  `try/catch`, просто `throw new HttpError(404, '...')` или `HttpError.notFound()`.
- Формат ошибки API: `{ "error": "текст", "details"?: [{ field, message }] }`.
- Prisma зафиксирована на версии 6 (в 7 другой способ подключения к БД).
